== Changes made in this round (24-4-2026, part 2) ===============================

  1. Empty-scan regression fixed.
     - The previous round added a manual esp_wifi_set_config() tweak
       to flip pmf_cfg.capable on the STA. arduino-esp32 v3.x already
       sets PMF capable by default; the manual fiddle was redundant
       and left the STA in a state where scanNetworks() returned 0
       on some boots. Removed it -- country "01" and scan
       parameters stay.
     - netScanNow() now logs "net: scan found N network(s)" so a
       no-results boot is visible without guessing.

  2. "boot: L=0 M=0 R=0" flood fixed.
     - The button diagnostic was firing every 2 s, which meant a
       steady stream of lines whenever the device sat on the setup
       screen. Reworked to edge-triggered: idle is silent, each
       button press emits one line, each release emits one more.
       Same debug value, zero noise at rest.



== Changes made in this round (24-4-2026) =======================================

  1. Morse "R" -- faster chirp, same volume.
     - Dot unit dropped from 120 ms to 40 ms. PARIS standard timing:
       30 WPM = 50 units per word / 60 s * 30 = 25 units/s, so
       1 unit = 40 ms.
     - Volume stays at 2/5 (sample amplitude 4800 of 12000 max).
     - Tail silence shortened to 120 ms so the whole chirp fits in
       ~560 ms of audio + tail.

  2. CLI is now live during every boot-time blocking wait.
     - bootTick() now calls cliPoll() alongside the input / dim /
       reboot-combo checks. That makes the serial CLI usable during:
         (a) the 4 s scan review window,
         (b) every per-slot connect attempt (via netAbortOnRightButton),
         (c) the setup-mode idle loop (cliWaitForNewNetwork),
         (d) all of the above even while the phone is banging on the
             captive-portal AP.
     - Effect: `sleep`, `reboot`, `wifi add`, `wifi connect`, `cancel`
       etc. work from the prompt at any point after power-on.

  3. Pixel hotspot still invisible -- more CLI tools to attack it.
     - All the firmware-side fixes from the previous round remain in
       place (country "01", PMF capable, showHidden scan, 300 ms
       channel dwell). They broaden what the radio *can* see / join;
       they don't force a phone AP that isn't beaconing to appear.
     - Two new CLI commands for the tail of the debug funnel:
         * `wifi scan-hard` (alias `rescan`) -- three back-to-back
           scans with a 500 ms gap. Phone hotspots beacon only every
           ~2 s, so a single pass can genuinely miss them.
         * `wifi connect <ssid> [password]` -- force-try an SSID
           without relying on the scan. Supports quoted SSIDs with
           spaces. If the association succeeds it offers to save.
     - Empty-scan output now prints the on-phone checklist
       (2.4 GHz / WPA2 or WPA2-3 / toggle hotspot to refresh beacon).
       The LCD scan screen has shown the same tips since last round.
     - If after all this the radio still can't see or associate with
       the Pixel hotspot, the explanation is almost certainly:
         (a) AP Band set to 5 GHz -- ESP32-S3 is 2.4 GHz only; the
             only fix is on the phone.
         (b) Security set to WPA3-Personal *only*. Switch to WPA2, or
             enable "Extend compatibility" if the Pixel offers it.
         (c) Auto-off-when-idle: keep the laptop connected while you
             try to join with the radio, or disable the timeout in
             hotspot settings.
     - Pixel 8 path: Settings -> Network & internet -> Hotspot &
       tethering -> Wi-Fi hotspot -> AP Band -> 2.4 GHz preferred,
       Security -> WPA2-Personal (or WPA3 with compat).

  4. WiFi scan now shows channel.
     - ScanResult gained a uint8_t channel, populated from
       WiFi.channel(i) in netScanNow().
     - CLI `wifi scan` / `wifi scan-hard` prints a "chNN" column
       between RSSI and the security label.
     - LCD scan screen shows the same "chNN" in cyan before each
       SSID so you can see at a glance if anything is beaconing on
       12 / 13.

  5. "Stuck on setup screen" escape hatches.
     - New top-level CLI commands: `cancel` (alias `exit`). Sets a
       flag that makes cliWaitForNewNetwork() return immediately
       without a new saved network. The orchestrator then falls back
       into netConnect(); if nothing joins, we drop into setup again
       -- but at least the user is not trapped.
     - bootTick() now prints a low-rate diagnostic line every 2 s,
       "boot: L=0 M=0 R=0", so "my buttons don't work" reports can
       be debugged: if the line never prints, bootTick isn't running;
       if it prints with the expected 1-on-press transitions,
       inputPoll is fine and the bug is in dispatch; if a held
       button never shows 1, the GPIO isn't seeing the press.
     - The setup-mode prompt now explicitly lists all three ways
       out: `wifi add`, `wifi connect <ssid> [pass]`, or `cancel`.


== Changes made in earlier round (23-4-2026) ====================================

  1. CLI commands + subcommands are now case-insensitive.
     - Top-level commands already used eqi() (case-insensitive). The
       bug was in the subcommand dispatch: `arg.startsWith("add")`
       and friends were case-sensitive, so `wifi ADD foo` or
       `SD reload` silently failed.
     - Added splitArg(arg, first, rest) in cli.cpp so every
       subcommand gets an eqi() match. Remainders (SSIDs, URLs,
       paths, passwords) stay case-preserving.
     - Added `wifi rm` / `wifi del` as aliases for `wifi remove`,
       and `wifi mv` for `wifi move`. `wifi show` now aliases
       `wifi list`.

  2. Pixel hotspot STA-side fixes.
     - The radio is the STA trying to join the phone's hotspot.
       Three firmware-side fixes applied:
         (a) Regulatory domain. WiFi.begin() defaults to US channels
             1..11; Pixel hotspots often pick ch 12 or 13.
             netBegin() now calls esp_wifi_set_country() with the
             ITU "01" world code (schan=1, nchan=13) so the full
             2.4 GHz band is visible.
         (b) PMF / WPA3. Pixel 8 hotspots frequently offer
             WPA3-Personal which requires Protected Management
             Frames. STA is tagged pmf_cfg.capable = true so we can
             associate with WPA3/PMF networks (and still with WPA2).
         (c) Scan covers more APs. netScanNow() now does an active
             scan with showHidden=true and a 300 ms per-channel
             dwell, so slow-beacon / probe-reply APs show up too.

  3. Deep sleep before WiFi now works.
     - The blocking waits in setup() never called inputPoll(), so
       the Left-button sleep request was ignored until loop()
       started. bootTick() centralises the "always works" behaviours
       and is plumbed into every blocking wait.

  4. Backlight dimming also works before WiFi.
     - Same bootTick() helper drives displayBacklightTick.

  5. "Untested features" flagged.
