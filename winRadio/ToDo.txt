== Changes made in this round (3-5-2026) ========================================

WiFi: on-device picker
-----------------------
  1. New display modes DM_WIFI_PICKER + DM_WIFI_CONNECT. From the
     System-info screen, a second long-press on the Right button
     (>= 2 s) opens the WiFi picker.
  2. Picker layout mirrors the station picker: 3x3 grid of cards,
     paged. Each card shows the SSID (wrapped to 2 lines) and a
     small 4-bar signal-strength indicator in the top-right.
  3. Mid short = advance cursor in reading order (auto-pages every
     9 cells, wraps); Mid double-click = connect to the highlighted
     SSID; Left or Right short = cancel back to System info.
  4. On select: looks up the SSID in the saved-credentials list. If
     found, uses the stored password; otherwise tries open auth.
     Switches to the DM_WIFI_CONNECT screen showing "Connecting to
     <ssid>...", a growing dot indicator and an elapsed-seconds
     counter. Repaint runs inline at ~5 Hz from netConnectAdhoc's
     progress callback so the UI doesn't freeze.
  5. On success: SSID/password are persisted via wifiAddNetwork
     (which updates in place if the SSID was already saved), audio
     is reconnected via audioStartLast(), and the screen switches
     to Now Playing.
  6. On failure: shows a brief "Saved password failed." or "Open
     auth failed." message for 1.5 s, then falls back to the WiFi
     picker so the user can pick another network.
  7. While the picker scan is running (~2-3 s blocking), a quick
     "Scanning WiFi..." status message is shown in place of the
     stale System-info screen.

WiFi: improved CLI connect flow
--------------------------------
  8. `wifi connect <ssid>` (no password): now looks up stored
     credentials for that SSID and uses them; if none are saved
     it tries open auth on the first attempt, then prompts for
     a password if that fails.
  9. `wifi connect <ssid> <pass>`: ad-hoc connect with the supplied
     password; offered to save on success.
 10. If a stored password fails (AP password rotated), the CLI
     prompts for a replacement and updates the saved entry on
     successful retry.
 11. New shared progress callback type (void(*)(uint32_t)) on
     netConnectAdhoc and tryJoin so callers (CLI, on-device
     picker) can render their own progress UI. CLI prints a dot
     every ~750 ms during the join.

Stations: CLI search + standalone defaults
-------------------------------------------
 12. New CLI `find` command set:
       find <text>           -- name search
       find tag <tag>        -- genre search
       find country <name>   -- country search
       find list             -- show last results
       find play <n>         -- preview hit N (no save)
       find save <n>         -- append hit N to the station list
     Backed by the existing discoverSearch() Radio-Browser client
     (the same code the /discover web page uses), so feature parity
     is automatic.
 13. New file: winRadio/stations_defaults.h. The compiled-in seed
     list now lives there as a single inline-constexpr array. To
     change the factory default stations: edit stations_defaults.h,
     rebuild, and (if you want existing flashed units to reseed)
     run "station reset-all" via the CLI / web. stations.cpp is
     unchanged from a code structure point of view; it just pulls
     the array in via #include.


== Changes made in this round (2-5-2026) ========================================

On-device navigation: two new LCD modes
----------------------------------------
  1. System-info screen (DM_SYS_INFO).
     - Entered by long press on the Right button (>= 2 s).
     - Shows: battery voltage + 5-bar level, WiFi SSID, signal as a
       5-bar meter + dBm, IP address, "<host>.local" hostname.
     - Exits on any short press (Left, Mid or Right).
     - Long-presses still pass through, so a long-press on Left
       still puts the radio to sleep, etc.

  2. Station picker (DM_PICKER).
     - Entered by long press on the Middle button (>= 2 s).
     - 3x3 grid of station cards. Each card shows the slot number
       and the friendly name (wrapped to 2 lines if needed). The
       currently-playing slot is shaded; the cursor cell is yellow.
     - Mid short press = advance the cursor through the grid in
       reading order (top-left -> bottom-right). At the bottom-right
       the next short press moves to the next page of 9; the last
       page wraps back to slot 0.
     - Mid double-click = select the highlighted slot
       (audioSelectStation + close).
     - Left or Right short press = cancel and return to the previous
       home mode.
     - Footer shows page indicator (e.g. "p2/4") when there's more
       than one page.

  3. Input state machine: Mid and Right now share the same
     short/double/long state machine as Left. Consequence: NEXT
     (Mid short) now fires on RELEASE rather than on press, after
     a 350 ms double-click window. Right has no double-click so
     VOL_UP fires on release with no extra delay.

  4. New input events: INPUT_PICKER_OPEN (mid long), INPUT_SYS_INFO
     (right long), INPUT_PICKER_SELECT (mid double).

  5. Main-loop dispatcher is mode-aware:
     - In DM_SYS_INFO any short press calls displayModalClose() and
       eats the event.
     - In DM_PICKER, Mid short = advance, Mid double = select,
       Left/Right short = cancel; all eaten so they don't double-
       fire as their normal "global" actions.

  6. New net helper: netCurrentSsid() returns the associated SSID
     (empty when not connected), so display.cpp doesn't have to
     reach directly into <WiFi.h>.



== Changes made in this round (1-5-2026) ========================================

6-axis IMU
-----------
  1. New imu.{h,cpp} module. Auto-probes the I2C bus at 0x6A / 0x6B
     for the QMI8658C chip-ID register (0x00 = 0x05). If found,
     initialises it for 125 Hz accel at +/-2 g (gyro left off --
     not needed for our two use cases, saves power). If not found,
     logs an I2C scan of all visible devices and disables IMU
     features -- the rest of the firmware keeps working.
  2. imuLoop() polls at ~10 Hz from the main loop(). It exposes:
       - imuMotionEvent()   : one-shot when frame-to-frame accel
         magnitude jerks by >0.12 g (picked up, tapped, shaken).
       - imuFaceDownEvent() : debounced 300 ms face-down transition.
       - imuFaceUpEvent()   : debounced 300 ms face-up transition.
     Classification is on the smoothed gravity vector (EMA alpha
     0.2); face-up = Az > +0.6 g, face-down = Az < -0.6 g.
  3. Motion-wake: imuMotionEvent() -> displayNoteActivity(), so
     picking up the radio un-dims the backlight without needing to
     hit a button.
  4. Face-down pause: when the unit is turned screen-down, audio is
     auto-paused and a flag remembers we did it. On the next face-up
     transition, playback resumes (only if WE paused it -- a manual
     pause with the Left button won't be undone by a flip).

Stations: variable-count list (0..30)
--------------------------------------
  5. Station list is now a packed NVS list, not a fixed set of
     "defaults + per-slot overrides". stationsBegin() restores from
     NVS; on first boot it seeds from SD /stations.csv or the
     compiled defaults and persists the seed.
  6. New public API: stationsMax(), stationsAdd(name,url),
     stationsDelete(idx), stationsEdit(idx,name,url),
     stationsResetToDefaults(). The old override-layer functions
     (stationsOverrideName/Url, stationsResetSlot, stationsSetSlot,
     stationsApplyOverrides, stationsUseDefaults) are gone.
  7. Web: home-page Stations card shows N / 30 usage and a "+ Add
     station" button that opens the existing edit modal with n=-1.
     The edit modal now has a Delete button (confirm-guarded) that
     posts to a new /api/station-del endpoint. The list shifts down
     on delete so the visible order stays contiguous.
  8. /discover Save defaults to "+ Add to list" instead of
     "Replace slot 1". The slot-pick dropdown still offers explicit
     Replace slot X... for deliberate overwrites, which is handy
     when the list is full.
  9. CLI: "station add" (interactive append), "station del <n>",
     "station reset-all" (wipe + reseed defaults). "station reset
     <n>" (single-slot clear-override) is gone -- there's no longer
     an override layer to clear.
 10. audioStationDisplayName() simplified: stored name wins unless
     it IS the URL (fallback state from an Add with no name); in
     that case the URL-derived prettifier runs. Covers Discover
     saves where the Radio-Browser entry had an empty name.
 11. audioNextStation / audioPrevStation guard against an empty
     list (avoiding the modulo-by-zero that a fully-deleted list
     would have produced).

Discover HTTP -1

== Design notes: MP3 player from SD (item 6) ====================================

Architecture sketch. Not implemented yet; captured here so the
wiring can happen in a self-contained future commit.

Goals
  * Play MP3 / AAC / OGG from /music/ on SD, with optional sub-
    directories per album / playlist.
  * Standard playlist formats: .m3u / .m3u8 (line-per-file),
    .pls (Shoutcast format), .xspf (XML; optional later).
  * Shuffle / repeat modes + a "resume last playlist position"
    across reboots.
  * Metadata: ID3v2 for MP3, ATOM boxes for AAC, Vorbis comments
    for OGG. ESP32-audioI2S already parses these and emits
    evt_id3data / evt_streamtitle.

Module boundary: new player_sd.{h,cpp}
  API:
    bool        playerSdBegin();            // pull SD, scan /music/
    int         playerSdPlaylistCount();    // number of .m3u files
    const char *playerSdPlaylistName(int);
    bool        playerSdLoadPlaylist(const char *path);
    bool        playerSdPlay(int track);    // 0-based
    bool        playerSdNext();
    bool        playerSdPrev();
    bool        playerSdPause();
    void        playerSdStop();
    int         playerSdCurrentTrack();
    int         playerSdTrackCount();
    const char *playerSdTrackPath(int);
    void        playerSdSetShuffle(bool);
    void        playerSdSetRepeat(int);     // 0=off, 1=track, 2=all

Storage:
  * Active playlist lives in RAM as a dynamic std::vector<String>
    (paths into /music/). Bounded at kMaxTracksInPlaylist = 512
    to keep RAM predictable.
  * Resume state in NVS: keys "player/lastpl" (path), "player/
    lastidx" (int), "player/shuffle" (bool), "player/repeat" (int).

Playback:
  * audio.connecttoFS(SD_MMC, path) starts a file; seek support
    via audio.setFilePos().
  * On evt_eof: advance index per shuffle / repeat, call
    connecttoFS on the new path.
  * Radio-mode vs SD-player-mode is tracked by an "audioSource" enum
    in the audio module: AUDIO_SRC_STREAM vs AUDIO_SRC_SDFILE.
    audioSelectStation switches to STREAM; playerSdPlay switches
    to SDFILE.

UI hooks:
  * Web: new /files page with a directory listing of /music/, plus
    a playlist editor (drag-reorder). POST /api/player/play
    {path=..., track=...}.
  * LCD: reuse the now-playing card, with display name coming from
    playerSdCurrentTrack's ID3 tag (title + artist); the station
    switcher row gets repurposed as a small "track X of N" +
    prev/next if we're in SD mode.
  * CLI: new `play <path>` / `play ls [dir]` / `play list` / `play
    shuffle on|off` commands.

Risks:
  * SD + network + audio task can fight for SPI / PSRAM. Start
    with mode-exclusive (only one source at a time) rather than
    crossfade.
  * ID3v2 tags with album art can be megabytes; parse only title +
    artist + length fields and skip the rest.


== Design notes: web-radio station discovery (item 7) ===========================

Goals
  * In-device discovery of internet radio stations (genre / search)
    without leaving the radio.
  * Add-to-favourites with one click -> goes into the overrides
    layer that's already in stations.cpp.

Back-end choice (cheap first):
  * Radio-Browser Community API:
      https://api.radio-browser.info/
      https://de1.api.radio-browser.info/json/stations/search?name=...
    Free, no auth, CORS-friendly, returns JSON with station name /
    URL / bitrate / codec / country / tags.
  * Fallback: Shoutcast YP API (legacy). TuneIn needs a key.

Module boundary: new discover.{h,cpp}
  API:
    struct Hit { String name, url, codec; int bitrate; String country; };
    int   discoverSearch(const char *query, Hit *out, int maxOut);
    int   discoverByGenre(const char *genre, Hit *out, int maxOut);
    bool  discoverSaveHit(int slot, const Hit &h); // -> stationsSetSlot
    int   discoverTopTags(String *out, int maxOut); // cache of common tags

Implementation sketch:
  * Use HTTPClient to GET the API with a User-Agent of
    "ON8CIT-WebRadio/0.3". Radio-Browser requires a UA header.
  * Parse JSON with ArduinoJson (add to lib_deps). Typical response
    is < 10 KB for 30 hits; stream-parse to avoid heap pressure.
  * Cache last query + results so paging between the LCD and web
    doesn't re-hit the API.

UI hooks:
  * Web: /discover page. Genre chips (top 12 tags), search box,
    results list. Each hit has a "Save to slot N" dropdown that
    POSTs to /api/station-edit (already implemented).
  * LCD: skip an LCD UX in v1 -- the discover flow is
    fundamentally long (typing a query, picking a hit) and the web
    UI is a better surface.
  * CLI: `discover search "jazz"`, `discover save 3 <hit#>` for
    headless workflow.

Privacy / rate limits:
  * Radio-Browser asks for a UA and ~1 QPS per client. Not an
    issue for human-driven search.

== Changes made in this round (24-4-2026) =======================================

  1. Morse "R" -- faster chirp, same volume.
     - Dot unit dropped from 120 ms to 40 ms. PARIS standard timing:
       30 WPM = 50 units per word / 60 s * 30 = 25 units/s, so
       1 unit = 40 ms.
     - Volume stays at 2/5 (sample amplitude 4800 of 12000 max).
     - Tail silence shortened to 120 ms so the whole chirp fits in
       ~560 ms of audio + tail.

  2. CLI is now live during every boot-time blocking wait.
     - bootTick() now calls cliPoll() alongside the input / dim /
       reboot-combo checks. That makes the serial CLI usable during:
         (a) the 4 s scan review window,
         (b) every per-slot connect attempt (via netAbortOnRightButton),
         (c) the setup-mode idle loop (cliWaitForNewNetwork),
         (d) all of the above even while the phone is banging on the
             captive-portal AP.
     - Effect: `sleep`, `reboot`, `wifi add`, `wifi connect`, `cancel`
       etc. work from the prompt at any point after power-on.

  3. Pixel hotspot still invisible -- more CLI tools to attack it.
     - All the firmware-side fixes from the previous round remain in
       place (country "01", PMF capable, showHidden scan, 300 ms
       channel dwell). They broaden what the radio *can* see / join;
       they don't force a phone AP that isn't beaconing to appear.
     - Two new CLI commands for the tail of the debug funnel:
         * `wifi scan-hard` (alias `rescan`) -- three back-to-back
           scans with a 500 ms gap. Phone hotspots beacon only every
           ~2 s, so a single pass can genuinely miss them.
         * `wifi connect <ssid> [password]` -- force-try an SSID
           without relying on the scan. Supports quoted SSIDs with
           spaces. If the association succeeds it offers to save.
     - Empty-scan output now prints the on-phone checklist
       (2.4 GHz / WPA2 or WPA2-3 / toggle hotspot to refresh beacon).
       The LCD scan screen has shown the same tips since last round.
     - If after all this the radio still can't see or associate with
       the Pixel hotspot, the explanation is almost certainly:
         (a) AP Band set to 5 GHz -- ESP32-S3 is 2.4 GHz only; the
             only fix is on the phone.
         (b) Security set to WPA3-Personal *only*. Switch to WPA2, or
             enable "Extend compatibility" if the Pixel offers it.
         (c) Auto-off-when-idle: keep the laptop connected while you
             try to join with the radio, or disable the timeout in
             hotspot settings.
     - Pixel 8 path: Settings -> Network & internet -> Hotspot &
       tethering -> Wi-Fi hotspot -> AP Band -> 2.4 GHz preferred,
       Security -> WPA2-Personal (or WPA3 with compat).

  4. WiFi scan now shows channel.
     - ScanResult gained a uint8_t channel, populated from
       WiFi.channel(i) in netScanNow().
     - CLI `wifi scan` / `wifi scan-hard` prints a "chNN" column
       between RSSI and the security label.
     - LCD scan screen shows the same "chNN" in cyan before each
       SSID so you can see at a glance if anything is beaconing on
       12 / 13.

  5. "Stuck on setup screen" escape hatches.
     - New top-level CLI commands: `cancel` (alias `exit`). Sets a
       flag that makes cliWaitForNewNetwork() return immediately
       without a new saved network. The orchestrator then falls back
       into netConnect(); if nothing joins, we drop into setup again
       -- but at least the user is not trapped.
     - bootTick() now prints a low-rate diagnostic line every 2 s,
       "boot: L=0 M=0 R=0", so "my buttons don't work" reports can
       be debugged: if the line never prints, bootTick isn't running;
       if it prints with the expected 1-on-press transitions,
       inputPoll is fine and the bug is in dispatch; if a held
       button never shows 1, the GPIO isn't seeing the press.
     - The setup-mode prompt now explicitly lists all three ways
       out: `wifi add`, `wifi connect <ssid> [pass]`, or `cancel`.
