ON8CIT WebRadio -- to-do list (newest on top, completed work at the bottom)


== Open / next up ==============================================================

A. Log / last-connected network
   - Add a "last joined" mark in wifi list so it's easy to see which saved
     slot the radio is currently on; useful when you have several home/work
     networks stored.

B. mDNS health
   - ESPmDNS occasionally stops responding after a router reboot. Add a
     30 s heartbeat that re-calls MDNS.begin() if the service query stops
     resolving. (Low-effort; 10 lines in web.cpp.)

C. Theme JSON
   - Feed the `Theme` struct in display.cpp from a JSON file on SD so the
     device is skinnable without a recompile. Needs SD mount first.

D. Touch screen driver
   - input.h already declares the INPUT_TOUCH_TAP event. Pick the chip
     (XPT2046 vs GT911 depending on the board variant) and produce events.

E. Stations on SD + station editor
   - Replace the hardcoded preset list (stations.cpp) with a JSON file on
     SD. The web UI gets a dedicated /stations page for add / remove / edit
     / reorder -- same UX pattern as the wifi list in the CLI today.

F. Recording
   - storage.h stubs call it out. Write the raw stream chunks plus an
     index sidecar so seeking works. Needs SD.

G. Power-aware display dimming
   - Ramp down backlight after N minutes of idle; wake on any button or
     web request. Simple analogWrite(PIN_LCD_BL, ...) in power.cpp.

H. mDNS during AP provisioning
   - Already pointed the DNSServer to answer everything with the AP's IP
     (so http://radio.setup works), but adding mDNS here too would let
     macOS / iOS find http://on8cit-setup.local out of the box.

I. Volume with steps > 5
   - The on-screen bar and the button step both assume 1..5. The Audio
     library accepts 0..21; 5 steps is very coarse.  Map buttons to
     "big step" and the web UI to "fine" (1..21)

J. Stereo / mono toggle + EQ
   - ESP32-audioI2S has bass / mid / treble setters. A little EQ panel in
     the web UI would be a very cheap UX win.


== Changes made in the latest round =============================================

(22-4-2026 follow-up.)

  0. Boot Morse "R" quieter.
     - Sample amplitude in audioPlayMorseR() scaled to the equivalent of
       user volume level 2 (was level-5-ish full-scale).
     - NB: the boot chirp runs before the Audio library starts, so it
       uses a compile-time constant rather than audioVolume(). If you
       want the chirp to match whichever volume you last set, reorder
       setup() so audioRestoreSession() runs before audioPlayMorseR()
       and drop the constant in favour of audioVolume().


(22-4-2026, responding to the first "Updates" block below.)

  1. Auto-reboot after AP-based save.
     - POST /save responds with "radio will reboot in a moment", then
       provisionPoll() latches a 2 s timer and ESP.restart()s. No user
       action required.

  2. Physical reboot combo.
     - Holding Left + Right simultaneously for 3 s triggers ESP.restart()
       from the main loop (input.cpp: inputRebootCombo).
     - The normal "left-press = deep sleep" event is suppressed while the
       right button is also pressed so the combo can win the race.

  3. Volume + station persisted across reboots.
     - Stored in the NVS "radio" namespace (keys "vol", "sta") on every
       audioSetVolume / audioSelectStation call.
     - audioRestoreSession() reads them at boot; audioStartLast() resumes
       the remembered slot instead of always starting at 0.

  4. AP renamed.
     - PROVISION_AP_SSID is now "ON8CIT-WinRadio-Setup".

  5. Web-based CLI.
     - After STA connect the sketch brings up a WebServer on port 80 and
       announces itself via mDNS as on8cit-radio.local. The home page
       shows a Now Playing card, Vol +/-, Prev/Next, a station grid that
       highlights the current slot, and a Reboot button.
     - REST-ish API for automation: GET /api/state (JSON snapshot), POST
       /api/station n=N, POST /api/next, /api/prev, /api/volume (v=N or
       d=+/-1), /api/reboot.
     - How to find the server on the LAN without typing the IP:
         - Primary: http://on8cit-radio.local (mDNS; works on macOS, iOS,
           Windows 10+, most modern Linux).
         - Secondary fallbacks (not yet implemented): periodic UDP
           broadcast with a JSON blob; SSDP announcement. Add later if
           mDNS proves unreliable on your router.

  6. OLED rework.
     - Main screen's 8-line station list replaced by a Now Playing card:
       big station name (derived from the URL via audioStationDisplayName
       -- e.g. groovesalad, radioparadise, radiocaroline), slot index
       "Station N of M", and the ICY-reported station name when the
       stream sends one.

  7. ON8CIT WebRadio banner.
     - New displayShowBootSplash() with a broadcast-waves logo +
       wordmark, shown while WiFi is scanning / connecting.
     - Every other setup screen (scan list, connecting, setup portal)
       wears a compact version of the same banner.
     - Main UI top bar now reads "ON8CIT WebRadio".
     - Every page served by the provisioning portal and the LAN web UI
       has the same ON8CIT WebRadio header band.

  8. Factoring stayed clean.
     - All changes landed inside the existing modules (config.h,
       storage.cpp, radio_audio.cpp, display.cpp, input.cpp, net.cpp,
       provision.cpp, web.cpp). The .ino orchestrator remained ~100
       lines. No new modules were needed this round.

Wifi Connection Logic implementation.
Requirements:
 1. Store multiple SSID/PWD combinations, tried one by one until a
    connection is made, re-orderable later.
 2. On startup show the SSIDs that are available (by WiFi scan) and their
    relative signal strength. Limit to the screen size.
 3. If, before a connection is made, button 3 is pressed then enter WiFi
    Setup mode to add another SSID.
 4. WiFi Setup happens in one of two ways:
    A. CLI -- select from the scanned list or type an SSID.
    B. AP "WS-InternetRadio" hosting a setup webpage.
    C. AP only active during credential gathering.
